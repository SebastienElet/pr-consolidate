# Context and Recovery Boundaries

## Repository context

The installed skill is not the target checkout. Read the origin and remote primary branch from
the current repository. Reject missing, ambiguous, unsupported or credential-bearing remotes
without printing their raw sensitive value. Do not silently substitute another remote or branch.
Recheck identity before publication and keep campaign clone origins consistent with that context.

## Campaign ownership

The source clone receives imported refs; it must belong to the campaign. Push and integration
clones also belong to that campaign. A clone isolates Git state only. Project setup determines
database, service and container isolation; configuration prose cannot certify those resources.

## Moving inputs

New source commits require another assessment. A source merged independently into the primary
branch requires reassessing its contribution. Check the current base and candidate with native
Git before delivery; a clean merge applies only to that exact pair and merge strategy.

## Review and replacement

Original-source reviews describe original heads. Label aggregate fixes and execution separately.
A timeout may happen after a successful remote write: reconcile the account, exact marker,
complete comment listing and current head before retrying. Preserve old-head assessments and
other accounts' comments.

Only replace a PR after merge verification, expected-head and ancestry checks, and its own review.
Resume a closed source only when the expected head and replacement record identify that operation.
An arbitrary closed PR is not proof of an earlier successful replacement.
